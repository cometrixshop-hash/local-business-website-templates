How to Host a Small Business Website Free on GitHub Pages, Netlify or Cloudflare Pages

Published 2026-11-07 · Cometrix Web Studio guides

If your business website is a set of plain HTML, CSS and image files (a "static site"), you may not need to pay for hosting at all. GitHub Pages, Netlify and Cloudflare Pages all offer free plans that serve static sites quickly, with free HTTPS. This guide explains how each works, what the limits are, and how to connect your own domain, so you can pick the right one and publish in an afternoon.

Is a static site right for your business?

A static site is a good fit if your website is mainly information: who you are, what you do, where you work, how to reach you. That describes most plumbers, electricians, landscapers, cleaners, salons, auto shops and consultants. It's not a good fit if you need customer logins, an online store with inventory, or content that a non-technical team edits daily (a content management system may suit that better).

Static sites have real advantages for small businesses: they load fast, there's no database or plugin to hack or keep updated, and hosting is cheap or free. Contact forms, which are the one "dynamic" feature most service businesses need, can be handled by a form service; see How to add a contact form to a static site.

Before you start: get your files ready

  • Put everything in one folder, with your home page named index.html at the top level.
  • Use relative links (img/van.jpg, not C:\Users\me\Desktop\site\img\van.jpg).
  • Keep file names lowercase with no spaces (water-heater.jpg). Many hosts are case-sensitive.
  • Open index.html in a browser locally and click every link to make sure nothing points to a file on your computer.

Option 1: Netlify

Good for: the easiest start, and built-in form handling.

How to publish

  1. Create a free account at netlify.com.
  2. Use the drag-and-drop publisher: Netlify's deploy documentation describes dragging your project folder onto the deploy zone, after which the site goes live on a unique URL.
  3. Alternatively, connect a Git repository (GitHub, GitLab, Bitbucket) so every change you push is deployed automatically.
  4. Rename the site in its settings to get a friendlier address like acme-plumbing.netlify.app.

What the free plan includes

Netlify's pricing page lists the Free plan at $0 with custom domains with SSL, a global CDN and a monthly usage credit allowance. Netlify moved to credit-based pricing, where actions like production deploys and bandwidth consume credits, so check the current numbers on that page before you rely on it for a busy site. For a typical small business site that's updated occasionally, usage is low.

Netlify also has built-in form handling. According to its forms billing documentation, forms are free and unlimited on credit-based plans.

Option 2: Cloudflare Pages

Good for: generous free limits and a large global network.

How to publish

  1. Create a free Cloudflare account.
  2. In the dashboard, go to Workers & Pages and create a Pages project.
  3. Choose Direct Upload, which supports dragging a zip file or a folder of assets, or connect a Git repository.
  4. Your site will be served at your-project.pages.dev.

Free plan limits

Cloudflare's Pages limits page lists, for the Free plan: 500 builds per month, up to 20,000 files per site, a 25 MiB maximum size per file, and up to 100 custom domains per project. A small business site uses a tiny fraction of that.

Cloudflare Pages doesn't have a built-in form inbox like Netlify, but a service like Formspree works fine (Cloudflare even has a tutorial for adding a Formspree form).

Option 3: GitHub Pages

Good for: people already comfortable with GitHub, portfolios, documentation and project sites.

An important caveat for businesses

GitHub's GitHub Pages limits page says Pages is not intended for or allowed to be used as a free web-hosting service to run your online business, e-commerce site, or any other website primarily directed at facilitating commercial transactions. Read the wording yourself. Many people host simple informational sites there, but if your site is your main business storefront, Netlify or Cloudflare Pages are the more comfortable choice. (Read their terms too; it only takes a few minutes.)

How to publish

  1. Create a repository on GitHub and upload your site files (the web interface lets you drag files in).
  2. Go to the repository's Settings → Pages.
  3. Under "Build and deployment," choose Deploy from a branch, then select your branch (usually main) and folder, as described in GitHub's publishing source docs.
  4. Your site appears at username.github.io/repository-name/ within a minute or two.
  5. Add an empty file named .nojekyll if you don't want GitHub's Jekyll processing to touch your files.

Limits

The same limits page lists a 1 GB maximum published site size, a soft bandwidth limit of 100 GB per month, and a soft limit of 10 builds per hour (unless you deploy with a custom GitHub Actions workflow).

Connecting your own domain

Buy a domain from any registrar. Then:

  • Netlify: add the domain under your site's domain settings and follow the DNS instructions. Netlify's HTTPS documentation says it automatically provisions a Let's Encrypt certificate for custom domains and renews it.
  • Cloudflare Pages: add the domain under your project's Custom domains tab. If your DNS is already on Cloudflare, the records are created for you; see the custom domains docs.
  • GitHub Pages: enter the domain in Settings → Pages, then create DNS records. For an apex domain (example.com), GitHub's custom domain docs list four A records: 185.199.108.153, 185.199.109.153, 185.199.110.153 and 185.199.111.153. For www, add a CNAME pointing to username.github.io. GitHub also recommends against wildcard DNS records.

DNS changes can take a while to spread. Once the domain resolves, make sure HTTPS is on and enforced. On GitHub Pages that's the "Enforce HTTPS" checkbox; GitHub's HTTPS docs confirm all Pages sites, including those with correctly configured custom domains, support it.

After you publish

  1. Visit both http:// and https:// versions of your domain, with and without www, and confirm they all end up at the same secure address.
  2. Test your contact form end to end.
  3. Add your site to Google Search Console and submit a sitemap.
  4. Put the URL on your Google Business Profile; see the local SEO checklist.

Updating the site later

The day-to-day workflow matters more than the launch. Think about who will make changes and how often:

  • Occasional edits by one person: drag-and-drop deploys on Netlify or Cloudflare Pages are fine. Edit the files on your computer, then upload the whole folder again. Keep a dated copy of the folder before each change so you can roll back.
  • Regular edits or more than one editor: connect a Git repository. Every change is recorded, you can see who changed what, and pushing an update deploys it automatically on all three hosts.
  • Quick text fixes: on GitHub you can edit a file directly in the browser and commit it; the site republishes in a minute or two.

Whichever route you take, keep the master copy of your site somewhere other than the host (your computer plus a cloud backup, or a Git repository). If you ever need to switch providers, you just upload the same folder elsewhere and update your DNS.

Which should you choose?

If you want the simplest path and need a contact form, start with Netlify. If you already use Cloudflare for your domain's DNS, Cloudflare Pages is a natural fit. If you're comfortable with GitHub and your site is a portfolio or project page rather than a business storefront, GitHub Pages works well. Because a static site is just files, you can move between them later in minutes, which is one more reason static hosting is a low-risk choice.
